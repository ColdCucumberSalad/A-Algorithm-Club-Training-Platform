# 德扑牌桌与动画

本次调整仅改变前端展示。发牌、下注校验、牌型、结算、钱包和定时任务仍由现有后端负责。

## 设计来源与实现

- [Pip](https://github.com/playpip/pip-web)：参考座位沿桌沿分布、公共牌留位、玩家面前的筹码及手机操作区。
- [Elite-Poker](https://github.com/opadips/Elite-Poker)：参考行动倒计时、发牌、筹码移动和收池的视觉反馈。
- [PokerTH Web Client](https://github.com/narmod/pokerth-web-client)：参考快捷下注与行动状态的清晰区分。

牌桌、纸牌、筹码、音效与动画均在现有原生 JavaScript/CSS 中独立实现，没有复制上述项目的代码或图片，也没有引入其后端。基础按钮使用带 `pk-` 前缀的 daisyUI 5，组件 CSS 已本地打包，不依赖外部 CDN；许可证在 `static/vendor/daisyui/LICENSE`。

牌桌使用绿色绒面、深色缝线桌沿、浅纸色牌面和红/蓝/象牙/金色筹码。自己的座位固定在下沿。普通页面中，桌面是横向椭圆，手机是纵向椭圆；主界面导航造成的窄内容区也切换至紧凑布局。

加注金额与原“加注至”按钮合并为一个控件。输入框默认填写原建议加注金额（后端给出的本轮最低加注至总额，受可用筹码上限约束），可编辑，点击左侧“加注”或按回车提交。右侧数字输入框带独立内边框，小三角位于框内右端，展开最小、½ 底池、满池、最大四个快捷金额；选择后仅填入金额并收起菜单，不会直接下注。点击外侧或按 Escape 也会收起菜单。已删除滑动条及独立加注面板。

大屏牌桌区域居中，最大宽度 1320px，桌面高度随内容区宽度在 580–660px 间变化；2K、4K 窗口保持约 2:1 的桌面比例，避免无限横向拉伸。

## 全屏

- 电脑：全屏容器包含牌桌与完整操作台，操作台保留在画面下方；进入/退出按钮和 F 快捷键切换，Escape 退出。展开快捷金额时，第一次 Escape 只关闭快捷菜单。
- 手机：全屏采用横向牌桌，左上角显示退出按钮，手机非全屏时，操作按钮、加注输入与离桌横向一行显示。全屏音量与玩法按钮嵌入牌桌右上角，位于悬浮操作台下层，可被展开的操作台遮挡，展开/收起键仅保留箭头图标；操作台在右侧按数字宽度自适应的浮动窄栏中，操作按钮及文字均纵向排列，展开/收起按钮使用半透明背景。状态提示独立显示于游戏画面左下角，收起操作栏后仍可见；快捷金额菜单浮在窄栏左侧，避免被栏宽裁切。抽屉覆盖在牌桌上方，开合时牌桌始终铺满屏幕，尺寸不变；收起后可查看被遮挡的牌桌区域。收起后不可误触抽屉内按钮；轮到自己时会自动展开。旋转设备、普通数据刷新会保留全屏状态与同一行动的金额草稿。
- 优先请求浏览器原生全屏及横屏锁定；不支持时使用占满页面视口的横屏布局。竖握手机时旋转游戏内容，实际转为横屏后自动恢复正常方向。退出时释放方向锁、页面滚动与按钮焦点。
- 浏览器全屏和方向锁存在兼容性限制，页面布局后备方式不能保证隐藏系统/浏览器栏，参见 [Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API) 与 [ScreenOrientation.lock](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)。

## 全站人数限制

全站最多 10 名真人同时入座，跨团队、Coins 多人局、多人练习与人机练习共用限额。机器人不占真人名额；已申请离桌但尚未完成本手结算的玩家仍占名额。恢复自己的已有座位、继续操作和离桌不受满员限制。离桌实际删除座位后释放名额。

入座前在 PostgreSQL 事务中获取专用 advisory lock，核对全站人数，并持锁直至买入和插入座位提交。不同团队、不同房间的并发创建/加入不会争抢出第 11 个名额；拒绝入座不扣款、不留下创建失败的房间。大厅显示全站人数，满员时禁用创建入口，后端始终再次验证人数。

## 动画与数据

- 比较连续两次已展示的房间状态，仅对观察到的变化播放动画。普通轮询不重新创建牌桌，不重播动画；首次进入/重连直接展示当前局面。
- 新一手由牌堆向玩家发牌，公共牌按新增位置翻开；本轮下注从座位移向面前，换街时筹码向底池移动，结算时底池向各个有返还金额的座位移动。
- 动画不阻塞操作、不猜测遗漏的操作，也不提前改动筹码数值；真实牌局状态始终以 API 为准。
- 使用 Web Animations API，节点重绘、返回大厅、退出游戏、页面隐藏或开启减少动态效果时取消动画。减少动态效果模式保留结果、牌面、数值和行动提示。
- 保持原有 1.5 秒网络轮询。250 毫秒的本地倒计时刷新不产生请求。音效默认关闭，主动开启后才创建 Web Audio 音频，选项仅保存在当前浏览器。
- 加注控件内的菜单提供最小、半池、满池、最大四个快捷值。半池/满池在跟注后底池基础上计算，填写本轮累计“加注至”金额；值仍受后端给定的上下限约束。同一行动期间更新数据时保留输入、焦点与菜单状态。

## 独立筹码钱包

大厅展示剩余筹码（不含桌上筹码），右侧提供买入和提现。1 Coin 买入 1000 筹码；提现金额为整数 Coin，每 1000 筹码兑换 1 Coin，不足部分保留。钱包为账号共享，练习筹码不可兑换。

多人联机房间使用“底注（筹码）”作为每人入桌金额，默认 1000，最低为大盲注。入桌扣除筹码，离桌返还筹码，不自动兑换 Coin。Coin 钱包仅在买入/提现时记流水。

迁移 0058 将旧 Coins 牌桌及进行中手牌的金额乘以 1000，保留原始 Coin 价值。应用时需停止旧版 web/worker 后再迁移，避免旧版服务继续按原比例结算。该数据迁移仅在没有筹码钱包及正式牌桌数据的空库支持回退，有数据时拒绝回退。

本次验证：完整 PostgreSQL 45 项测试通过（含兑换和牌桌并发）；桌面/手机筹码钱包浏览器检查和现有牌桌浏览器回归通过。Docker 残留通讯目录已改名保留并重建，引擎恢复。已备份本地数据库并应用 0058，本地网站和后台服务已更新，实际页面的筹码余额、买入/提现和底注栏均已核对。

## 人机离桌

人机练习点击离桌立即关闭房间，清空本手状态与全部真人/机器人座位，释放全站真人名额，不等待机器人比牌；全下也适用，不影响 Coin 钱包、可兑换筹码或收入。关闭记录仅保留房间元信息供已有请求返回关闭状态，定时扫描不再推进。断线超过五分钟或账号失效也直接清理私人练习桌。多人房间仍按原有离桌和全下结算规则处理。

## iPhone 全屏容器修复

页面的 `.page-view` 带有 `perspective`，会改变后代固定定位元素的包含块。iPhone 浏览器不支持原生元素全屏时，原来的牌桌仍受页面容器限制，可能被裁成窄带。进入全屏先用占位节点记录原位置，再将整个 `#pokerView` 临时挂到 `body`；退出、返回大厅或关闭游戏时还原，保留原节点、牌局轮询及操作状态。

回归脚本 `tests/poker-fullscreen-shell.browser.mjs` 使用带 perspective、transform、filter 和 overflow 的页面外层容器，拒绝原生全屏，覆盖 402×680、390×844、844×390、667×375。Chromium 和 WebKit 验证视口覆盖、旋转、轮询中金额保留、退出及关闭清理；浏览器仿真不等同于实体 iPhone 测试。
