# LeetCode 过题身份与历史数据处理

## 统计规则

- 只绑定国服或国际服：以当前绑定的分区统一归档证明、现存有效证明、比赛归档和平台过题明细。同题只计一次，不根据旧证明链接的域名额外生成另一服的过题。
- 同时绑定两服：按题目 slug 去重，两服累计数量的保底取较大值，不相加。同服多个账号同样取较大保底；已知的不同题目明细仍保留。
- 未绑定 LeetCode：保留证明和归档证据，按 slug 去重；不推断平台累计数量。
- 同题有多个真实日期时保留最早日期；无日期的历史证据不补成今天。日期补全消耗既有总数保底，不额外增加累计数量。

例如：平台累计 79 题，其中一道旧题只有 `leetcode:two-sum` 归档。归并后显示总数 79、有日期 1、日期未知 78；不再显示 80。以后同步获得该题明细，仍然只计一题。

这些规则只读取本地数据库中的题目键、绑定和数量，不调用 AI API，也不发起远程平台请求。

## 历史数据方案

采用读取时归并，不批量改写或删除历史记录，不新增数据库迁移。历史的两段证明键 `leetcode:<slug>`、三段比赛键 `leetcode:<contest>:<slug>`，以及已带 `leetcode_cn:` / `leetcode_us:` 的证据，均在统计前按当前绑定归一。

该方案保留归档原键、来源和日期，支持源提交已经清理的历史记录。以后修改绑定分区或删除其中一服，下一次查询按新绑定重新归并，避免一次性数据迁移将旧记录永久归到错误分区。重复归档、重复查询不会新增证据或更改原数据。

部署步骤：

1. 将 PR36 的最新代码部署至 Web 和 Worker；此文档不表示已部署。
2. 总榜、学期过题和活动热力图都读取 `solved_evidence()`，已有 v2 账号无需重新同步，下一次请求即使用修正后的历史统计。
3. 对尚未启用 v2 同步的老绑定，先使用 `python manage.py refresh_bound_solved --user-id <用户编号>` 预览，再用相同命令加 `--apply` 入队升级；需要正常运行 Worker，并核对凭据。升级前继续走原有旧版基线逻辑，本次修复不会隐式升级账号。
4. 在数据副本核对单服、换服、双服、已清理源提交、平台明细补全等情况。对比原始归档行数和日期，确认原始证据未改写；核对原先重复计数的用户总数下降符合预期。

本修复只影响过题统计，不重算 Coins、积分或已经发放的奖励。若要追溯处理奖励，需要另行确认具体业务规则。
